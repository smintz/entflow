  <action>
Create `registry.go` in package `entflow`.

Declare an unexported `registryKey struct{}` as the context key type — never a string key, and never one `context.WithValue` call per provided concrete type. Store exactly one `*Registry` in the context; do the typed lookup inside it.

`Registry` holds a `sync.RWMutex` and `items map[reflect.Type]any`. `NewRegistry()` returns a `*Registry` with the map initialised.

`Provide[T any](r *Registry, v T)` takes the write lock and stores `v` under the key `reflect.TypeFor[T]()`. Use `reflect.TypeFor[T]()`, the Go 1.22+ stdlib generic helper — not the older `reflect.TypeOf((*T)(nil)).Elem()` boilerplate. Keying on `T` rather than on `reflect.TypeOf(v)` is what makes interface-typed registration work: `Provide[Refunder](reg, concrete)` must key on `Refunder`.

`WithRegistry(ctx, r)` returns `context.WithValue(ctx, registryKey{}, r)`.

`TryUse[T any](ctx) (T, error)` reads the registry from the context with a comma-ok assertion. Missing registry returns the zero `T` wrapped over `ErrNoRegistry`. Present registry but absent key returns the zero `T` wrapped with `%w` over `ErrNotProvided`, and the message must name the missing type via `%T` on the zero value so a wiring mistake is diagnosable from the error text alone. Take the read lock for the lookup.

`Use[T any](ctx) T` calls `TryUse[T]` and panics with the returned `error` VALUE on failure — never a formatted string and never a bare string literal. This is load-bearing for D-16: Plan 03's per-step `recover()` inspects the recovered value and, when it is already an `error`, threads it through as the `%w`-wrapped cause of a `*StepError`, so `errors.Is(err, entflow.ErrNotProvided)` still resolves after the panic has been converted to a returned error. A panic value that is not an `error` would break that chain.

Declare `ErrNoRegistry` and `ErrNotProvided` as distinct package-level sentinels via `errors.New`. They must be distinct values so a caller can tell "the executor never injected a registry" apart from "the developer forgot to provide this client".

Write `registry_test.go` covering every behavior listed above, including a `-race`-exercised concurrent test.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied bytes → `Codec.Unmarshal` | The only place in Phase 1 where entflow deserializes a byte slice. In Phase 1 the application supplies these bytes directly; in Phase 2 they arrive from the run row, so the parsing behaviour locked here is what Phase 2 inherits. |
| step body → DI registry | Step closures reach outside-the-schema handles only through `Use[T]`. The registry is the single choke point for what a step body can touch. |
| error text / `Describe()` output → logs and spans | Anything rendered into an error message reaches operator-visible surfaces. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Denial of Service | `codec.go` `JSONCodec.Unmarshal` on hostile or malformed input | medium | mitigate | `Unmarshal` returns an error on every malformed input and never panics — asserted by test. Deeply-nested input is bounded by `encoding/json`'s own recursion depth limit in the pinned Go 1.25 toolchain; entflow adds no unbounded recursion of its own on the decode path. `Unmarshal` is called once per execution, not in a loop. |
| T-01-05 | Information Disclosure | `codec.go` `Unmarshal` error text | medium | mitigate | Decode errors name the target type via `%T` but never embed the raw input bytes. A serialized flow input can carry PII or payment details (`.planning/research/PITFALLS.md`, Security Mistakes row 2); error strings reach logs and OTel span attributes, so the payload must not ride along. Asserted by a test that decodes a struct containing a secret-looking field from malformed bytes and checks the error text does not contain that value. |
| T-01-06 | Spoofing | `registry.go` provider registration keyed by `reflect.TypeFor[T]()` | low | accept | Any in-process code holding the `*Registry` can overwrite a provided handle. This is inherent to an in-process DI registry and is bounded by D-15's scoped design — there is no package-level global to poison, so the blast radius is one explicitly-constructed registry. Accepted: an attacker with in-process code execution has already won; the registry adds no new boundary. |
| T-01-07 | Tampering | `result.go` `Result[T]` type assertion | medium | mitigate | Every stored-value assertion uses the comma-ok form and returns `ErrResultTypeMismatch` rather than panicking. A panicking assertion here would let a step-name typo become an unrecovered crash on a rarely-hit conditional branch (`.planning/research/PITFALLS.md`, Pitfall 6 and the UX Pitfalls table). |
| T-01-SC | Tampering | Go module dependency graph | high | mitigate | No new module dependency is introduced by this plan — `registry.go`, `codec.go`, `result.go`, and `errors.go` import stdlib only (`context`, `encoding/json`, `errors`, `fmt`, `reflect`, `sync`, `runtime/debug`). The exact-pin plus `go.sum` checksum-database verification plus CI's `-mod=readonly` established in Plan 01 continue to apply. |
